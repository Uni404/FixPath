你的项目目录建议

先建一个总文件夹：

fixpath/

里面分成：

fixpath/
  frontend/
  backend/
  database/
  docs/

说明：

frontend/ 放 React
backend/ 放 Express
database/ 放 schema.sql、seed.sql
docs/ 放 diagram、API notes、截图
Day 1：搭环境 + 建数据库 + 明确主流程
目标

操作

npx create-react-app frontend
backend

进入 backend 文件夹：

npm init -y
npm install express mysql2 cors dotenv nodemon

建议再装一个接口日志工具：

npm install morgan
任务 2：建数据库
工具

任务 3：写 schema.sql

在 database/schema.sql 里保存所有建表语句。

再写 database/seed.sql，插入测试数据：

任务 4：明确主流程

今天把你系统最小闭环写在一个 txt 或 md 文件里：

User submits report
→ Backend stores report
→ DiagnosisEngine loads rules
→ Matches symptoms
→ Generates decision result
→ Returns result

这一步很重要，因为你后面所有开发都按这个走。

Day 3：实现 Diagnosis Engine
目标

今天要完成你项目最核心的东西：

diagnosis service
rule matching
save decision result
POST /diagnose/:reportId
任务 1：写 DiagnosisEngine
工具
Node.js
MySQL

放在：

backend/src/services/diagnosisEngine.js
核心逻辑
根据 reportId 查 report
查 report 的 symptom
根据 deviceId 查 applicable rules
查每条 rule 对应的 symptoms
做 subset matching
得到 outcome / risk
存入 DECISION_RESULT
任务 2：处理无匹配情况

这是必须的：

如果没有规则匹配，不要报废，要默认：

outcome = expert consultation
risk = uncertain

这会让你的系统更稳，也更符合 report。

任务 3：实现 POST /diagnose/:reportId
返回建议
{
  "resultId": 10,
  "outcome": "emergency stop",
  "riskLevel": "high",
  "recommendation": "Stop using the heater and contact a professional."
}
任务 4：准备几条可演示规则

例如：

Rule 1
device = heater
symptom = smoke
outcome = emergency stop
Rule 2
device = vacuum cleaner
symptom = weak suction
outcome = low-risk troubleshooting
Rule 3
symptom insufficient
outcome = expert consultation
今天的交付标准

今天结束时你必须拥有：

diagnosis engine 跑通
